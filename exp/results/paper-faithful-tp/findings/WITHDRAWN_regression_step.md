# 철회 — 별도 "프로토타입 회귀" 단계

한 번 만들었다가 돌리기 전에 철회했다. 기록으로 남긴다.

## 무엇을 만들었나

같은 저장소(TP 패치 적용됨)에서 두 arm 을 돌리려 했다:

```
released-prototype   @ TP 패치 적용된 트리
paper-faithful-v4    @ 같은 트리
```

## 왜 틀렸나

**비교 축이 질문과 맞지 않는다.** 회귀 질문은

> TP 패치를 넣은 뒤에도 프로토타입 경로가 그대로인가

이고, 답하려면 **같은 시스템을 다른 코드베이스에서** 돌려야 한다. 위 설계는
**같은 코드베이스에서 다른 시스템을** 돌린다. 그건 정책 비교(프로토타입 정책
대 Algorithm 1/2)이지 회귀 검증이 아니다. `paper-faithful-v4` arm 은 회귀
질문에 아무 정보도 주지 않는다.

두 번째 arm 을 넣은 이유는 "비교하려면 arm 이 둘 있어야 한다" 는 습관이었고,
그 습관이 축을 잘못 고르게 했다.

## 무엇이 대신하나

최종 비교 실험의 arm A/B 가 정확히 이 검증이다:

```
A  released-prototype  @ prism-base   TP 패치 없음
B  released-prototype  @ prism-merge  TP 패치 있으나 꺼짐
```

같은 시스템, 다른 코드베이스. 게다가 전 rate 를 3 seed 로 커버하고, 게이트로
먼저 돌려 통과 못 하면 본 스윕을 시작하지 않는다.

철회로 GPU 약 1시간을 아꼈고, 리포트에 답하지 않는 표가 하나 줄었다.
