# 수정 전 런 — 보존용

`_snap_to_group` 을 넣기 전의 4단계 첫 런이다. 결함(TP 모델이 재활성화되지 못하고
요청 1672건이 쌓임)의 증거이므로 지우지 않는다. 상세는
`../OPEN_DEFECT_tp_reactivation.md`.

이 런의 **요청/SLO 수치는 쓰지 말 것.** TP 모델이 대부분의 시간 내려가 있었으므로
결함을 재는 것이지 anti-affinity 를 재는 것이 아니다.

반면 아래는 이 런에서도 유효하다:
* TP 그룹 마이그레이션이 동작한다는 증거 (`[2,3]->[1,2]->[1,3]->[2,3]`)
* anti-affinity 반사실 (348 사이클, 위반 23, 충돌배치 계획 282) — 계획 단계
  기록이라 요청 타임아웃과 독립이다. 다만 수정 후에는 충돌 배치가 emit 자체가
  불가능해지므로 이 282 라는 숫자는 수정 후 런과 직접 비교하면 안 된다.
